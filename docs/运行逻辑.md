# NPR Shader 运行逻辑

本文回答两个问题：
**这个插件从头到尾实现了什么？** 以及 **它的工作流程是怎么走的？**

内容基于代码实读（文件与函数名都可直接检索），不是设计意图的复述。

---

## 一、插件到底实现了什么

一句话：**用 Python 在插件内部重建了参考文件 `OdetteV3.blend` 的整套三渲二着色节点组，
再在外面包一层"材质组"管理和一键应用**。

### 1.1 它解决的问题

Blender 的 NPR 材质通常靠一堆手工连的节点组实现，痛点是：

| 痛点 | 本插件的做法 |
|---|---|
| 节点组是外部资产，换机器/发文件就丢 | **全部由 Python 生成**，插件自带，不依赖任何 `.blend` |
| 每个材质调一遍，几十个材质调到崩 | 引入**材质组**，一组参数管一批材质 |
| 参考实现里的常量写死在节点里 | 全部**提升为组接口参数**，可在面板上调 |
| 描边要自己搭 Solidify | 内置倒角外壳描边，一键生成 |
| 换模型要重接贴图 | 按文件名+色彩空间**自动识别归类** |

### 1.2 代码结构（9 个模块，约 5400 行）

```
npr_shader/
├── __init__.py        注册入口、模块加载顺序、节点组构建的兜底机制
├── utils.py         (571) 底层工具：插槽解析、连线、贴图识别、日志、选择
├── properties.py    (629) 数据模型：材质组 / 材质引用 / 候选材质 / 设置 / 日志
├── shader_nodes.py (1937) ★ 18 个 Shader 节点组的 Python 构建器
├── outline.py       (350) 描边：Solidify 倒角外壳 + 修改器两种模式
├── presets.py       (262) 8 个预设组的参数与贴图槽定义
├── core.py          (680) 应用引擎：材质生成、贴图接线、参数下发、反读
├── operators.py     (644) 25+ 个操作符（用户能点的每个动作）
└── ui.py            (609) 15 个面板 + 3 个 UIList
```

依赖方向是单向的：

```
utils → properties → shader_nodes → outline → presets → core → operators → ui
```

（`__init__.py` 里的 `_MODULE_ORDER` 就是这个顺序，保证被依赖的先加载。）

### 1.3 18 个节点组

| 组名 | 作用 |
|---|---|
| `NPR_SmoothStep` | 归一化平滑阶跃（多处复用） |
| `NPR_Lambert` | 兰伯特光照项，输出 6 个通道 |
| `NPR_LightVector` | 由欧拉角算固定光向量 |
| `NPR_CameraVector` | 相机方向向量 |
| `NPR_HeadVector` | 头部坐标系（三点定义，用于面部朝向） |
| `NPR_RampAmount` | 由光照贴图 A 通道算 Ramp 条数量 |
| `NPR_RampSelect` | 按条数选 Ramp 行 |
| `NPR_NormalmapDecode` | 法线贴图解包 |
| `NPR_LightmapSmoothStep` | 光照贴图的平滑阶跃（AO 用） |
| `NPR_BlinnPhong` | 高光 |
| `NPR_Normalmap` | 法线合成 |
| `NPR_BaseColor` | **基础色选择链**：按 mask 选部位贴图 + 亮度 + 花纹叠加 + 色调 |
| `NPR_Lightmap` | 光照贴图分解（R/G/B/A 四个语义） |
| `NPR_Ramp` | 阴影 Ramp 采样 |
| `NPR_EyesShader` | 眼睛专用着色 |
| `NPR_AdditiveDetail` | 花纹叠加（Detail 1–4） |
| `NPR_Shader` | **主组**：把上面全部串起来，输出 Emission |
| `NPR_OutlineShader` | 描边纯色材质（插件新增，参考文件没有描边） |

### 1.4 着色链路（`NPR_Shader` 内部）

```
                     ┌─ LightVector ──┐
Light Euler ─────────┤                ├─ Lambert ─┐
NormalTex ── NormalmapDecode ─ Normalmap ────────┤
                                                  ▼
                                        ┌── 帧 AO / 阴影 ──┐
LightmapTex ── Lightmap ────────────────┤                  │
                     └─ LightmapSmoothStep                │
                                                          ▼
BaseColorTex ─┐                            ┌──── Ramp Mask ────┐
部位 mask ────┼─ NPR_BaseColor ───────────┤                   │
Base Color ───┘   （贴图选择+亮度+色调）    │                   │
                                          ▼                   ▼
                              ┌── 帧 Specular ──┐    ┌── 帧 Rim ──┐
                              │  BlinnPhong     │    │ LayerWeight│
                              │  MetalTex 遮罩  │    │ RimColor   │
                              └────────┬────────┘    └─────┬──────┘
                                       ▼                   ▼
                                  ADD（高光）  →  ADD（边缘光）
                                                     ▼
                                              Halo Brightness
                                                     ▼
                                                Emission 输出
```

**关键设计**：整条链输出到 **Emission**，所以着色**不依赖 EEVEE 的灯光**。
这是参考文件本身的特性（实测：加太阳灯前后渲染差异 0.0000）。

## 二、工作流程

### 2.1 插件加载流程

```
Blender 启动
   │
   ▼
addon_utils 读偏好 → 发现 npr_shader 已启用
   │
   ▼
__init__.py: register()
   ├─ _reload_modules()        重载 8 个子模块（支持热重载）
   ├─ 遍历 _MODULE_ORDER       逐个调用子模块的 register()
   │     properties → 注册 PropertyGroup
   │     operators  → 注册全部操作符
   │     ui         → 注册全部面板
   ├─ _schedule_deferred_build()  挂 load_post handler + timer（兜底）
   └─ _build_groups_now()        尝试构建 18 个节点组
          │
          ├─ 成功 → 完成
          └─ 失败（启动期 bpy.data 是 _RestrictData 代理）
                 → 留待后续触发
```

**为什么需要兜底**：Blender 在启动阶段（还没载入文件）把 `bpy.data` 包成一个
受限代理，访问 `bpy.data.node_groups` 会抛 `AttributeError`。如果这时硬要构建，
`register()` 会中断，插件就变成"偏好里勾了但没加载"（面板根本不出现）。

### 2.2 节点组构建流程（自愈）

节点组构建**不依赖**上面那次调用是否成功，任何一个入口都会先补齐：

```
用户点任意 NPR 按钮
   │
   ▼
NprOperator.__init_subclass__ 包装过的 execute()
   └─ ensure_groups()
        └─ shader_nodes.ensure_all()
             └─ 对 BUILD_ORDER 里每个组名:
                  needs_build = force
                              or 组不存在
                              or 版本标记过期
                              or _tree_is_healthy() == False   ← 关键
                  if needs_build: 调对应 builder() 重建并打版本标记
```

`_tree_is_healthy()` 检查**三件事**，任一不满足就重建：

1. 至少 2 个节点（Group Input + Group Output）
2. 内部有 Group Output 节点
3. 接口里至少有一个 OUTPUT 插槽

**为什么需要它**：只看"名字存在"是不够的。如果某个名字下已经躺着一个**空组**，
按名字判断会认为"已构建"而永远跳过 —— 材质里挂上的就是没有接口的空组，
表现为插件"装了但没效果"。

### 2.3 一键应用流程

```
bpy.ops.npr.apply()
   │
   ├─ 1. 取设置：mode / slot_mode / auto_texture_detect / 是否带描边
   ├─ 2. 取目标：context.selected_objects 里的网格
   ├─ 3. 确定材质组：settings.active_group()
   │        └─ 没选组且 auto_create_group → 自动建一个
   ├─ 4. 收集原材质贴图（若 auto_texture_detect）
   │        classify_texture() 按文件名关键词 + 色彩空间归类
   │        → {base_color: Image, lightmap: Image, normal: Image, ...}
   ├─ 5. 对每个物体、每个材质槽：
   │        ├─ REPLACE / REPLACE_KEEP_TEXTURES
   │        │     material = core.ensure_group_material(group, textures)
   │        │     slot.material = material
   │        ├─ APPEND
   │        │     新增槽位 → 指向 NPR 材质
   │        └─ OUTLINE_ONLY
   │              什么都不做（只走第 6 步）
   ├─ 6. 若启用描边 → outline.ensure_outline(...)
   └─ 7. utils.log(...) 写日志 + self.report 给 Blender 状态栏
```

### 2.4 材质生成流程（`core.ensure_group_material`）

```
ensure_group_material(group)
   │
   ├─ 材质名 = NPR_<组名>_<部位>（如 NPR_身体_Body）
   ├─ 已存在同名材质 且 里面有 NPR_Shader 主组实例？
   │     ├─ 是 且 不强制重建 → 直接复用，只刷新参数
   │     └─ 否 → _build_material_content() 重建
   ├─ _build_material_content():
   │     ├─ ensure_shader_groups()        ← 先自愈，避免拿到空组
   │     ├─ clear_node_tree()             清空（保证幂等）
   │     ├─ 建 NPR_Shader 主组实例
   │     ├─ 建 Material Output
   │     ├─ 按 MASTER_TEXTURE_SLOTS 接贴图节点 + UVMap
   │     └─ 接 Alpha 相关（若启用）
   └─ _configure_master_inputs()          把组参数写进主组接口
```

**材质里只有两个节点**：`NPR_Shader 主组` + `Material Output`。
贴图是作为**主组接口的取值**送进去的，不是挂在材质里。

这样设计的好处：材质树极简、参数集中在一处、替换材质时不会丢贴图引用。

### 2.5 材质分配流程（勾选式）

```
① 用户在「材质组管理」里点选目标组
      → settings.active_group_index

② 点「收集选中物体的材质」
      utils.selected_meshes()          → 选中的网格
      utils.mesh_material_slots()      → [(object, slot_index, material), ...]
      settings.picker_fill(slots)      → 填充 picker_items（按材质去重）
                                         每条记录 material + selected + source

③ 用户勾选（BoolProperty，直接改 item.selected）
      已在该组里的会显示「已在组内」提示

④ 点「把勾选的 N 个材质加入当前组」
      settings.picker_selected_materials() → 被勾选且有效的材质
      对每个材质:
          group.add_material(material)     写入 group.materials（去重）
          utils.set_material_group(...)    在材质上打 npr_group 元数据
```

`set_material_group()` 写入的元数据（存在材质的自定义属性里）是关键：

- `npr_group` = 组名
- `npr_part` = 部位

有了它，插件才能**从材质反查它属于哪个组**，从而支持：
「选中本组物体」、「从材质反读参数」、「组按材质反查」。

### 2.6 组参数下发流程

```
用户在面板改 group 的某个属性
   │
   ▼
点「应用到选中物体」/「一键应用」/「应用整组」
   │
   ▼
core.apply_group(context, group)
   ├─ 收集目标材质：
   │     ├─ 组内登记的材质（group.materials）
   │     └─ 场景里 npr_group 元数据指向本组的材质
   ├─ 对每个材质 → _configure_master_inputs(master, group)
   │     按 MASTER_TEXTURE_SLOTS / MASTER_VALUE_SLOTS /
   │        MASTER_COLOR_SLOTS / MASTER_FLAG_SLOTS 逐项 set_default
   └─ 返回 report（成功/失败数量）
```

**反读**（`read_back`）走反方向：读主组接口的实际取值 → 写回 group 属性。

### 2.7 描边流程

```
outline.ensure_outline(context, group, objects)
   │
   ├─ 模式 = MODIFIER
   │     └─ 给原对象加 Solidify 修改器
   │          offset=1.0 / use_flip_normals=True / 厚度=group.outline_width
   │
   └─ 模式 = SHELL（默认）
         ├─ 复制源对象网格 → 新对象 NPR_Outline_<组>_<源对象>
         ├─ 挂 Solidify（同上）
         ├─ 赋纯色描边材质 NPR_Outline_<组>
         │     use_backface_culling = True
         └─ 打标记 npr_outline_of = <源对象名>
```

重复执行时先按 `npr_outline_of` 标记查找已有外壳，**更新**而不是新建。

## 三、关键实现细节（踩坑记录）

这些是开发中实际踩到并修掉的坑，都写在对应位置的代码注释里。

### 3.1 `ShaderNodeMix` 的 `data_type` 必须在建节点时确定

默认是 `FLOAT`，此时 `A_Color` / `B_Color` / `Result_Color` **根本不存在**。
先按 FLOAT 连好线再改成 RGBA，Blender 会**静默丢弃**那些连线 ——
不报错，但结果不对。

→ `utils.mix_node()` 先设 `data_type`，再设 `blend_type`，并复核插槽集合。

### 3.2 `Mix(MULTIPLY)` 不可靠，颜色乘算改用拆通道

实测：在**节点组内**，`Mix(blend_type='MULTIPLY')` 于
`A=白 / B=目标色 / Factor=1` 时输出**两倍**目标色（红 0.1 → 0.1981）；
同一配置放在材质里却正常。行为随上下文变化。

→ 新增 `Edit.color_multiply()`：一律用
`SeparateColor → Math(MULTIPLY) ×3 → CombineColor` 实现颜色乘算。
适用于色调、增益、Ramp、自发光、边缘光、主组光环增益。

### 3.3 `Mix` 的 Factor 是混合权重，不是强度

语义是 `A*(1-F) + A⊗B*F`。对 MULTIPLY / ADD 来说 `F=0` 会退化成 `A`。
默认值 0.5 会让整条链只生效一半。

→ `_apply_blend_factors()` 把任何 **RGBA 且非 MIX** 的 Mix 节点、
在 Factor 未连线时统一补成 1.0（MIX 不碰，因为它是真的按权重插值）。

### 3.4 组接口 identifier 会随接口增删整体位移

节点组接口插槽的 identifier 是自动编号（`Socket_N`）。往中间插一个接口，
后面所有编号后移。曾导致 `Face←Body01`、`Body←Hair` 的连锁错位。

→ 子组→主组的连线**一律按名称**连接；新增接口一律**追加到末尾**。

### 3.5 Float → Mix.Color 不会被隐式转换

`ShaderNodeMath`（Float）直接接到 Mix 的 `A_Color`，连线会被丢弃。

→ 新增 `Edit.float_to_color()`，需要把标量接进颜色通路时显式转换。

### 3.6 `ShaderToRGB` 在 EEVEE Next 下失效

参考文件的 Rim / Emission 帧用了 `MixShader + ShaderToRGB`；
该节点在 4.2+ 对真实着色器输入返回黑色，会把整条链打成黑。

→ 改为等价数学式（LayerWeight + 幂次 + 归一化），并在文档里列为有意偏离。

### 3.7 高光分支依赖光照贴图

参考文件的高光由 `LmR` / `LmB`（光照贴图红蓝通道）+ 金属贴图驱动。
插件里这两张图默认是"白光照贴图 + 黑金属贴图"，此时该分支会退化成**白色 AO 项**，
直接 ADD 上去把画面顶成纯白。

→ 高光贡献额外乘 `MetalTex` 亮度作为遮罩：没有金属贴图 → 贡献为 0。

### 3.8 操作符 `execute` 必须恰好 2 个参数

给基类 `execute` 包自愈逻辑时，如果用"带默认值的第三参数"捕获原方法，
Blender 抛 `ValueError: expected Operator ... to have 2 args, found 3`，
**整个注册失败**。

→ 改用闭包捕获原方法，签名保持 `execute(self, context)`。

### 3.9 Blender 5.2 移除了 `Material.select`

无法询问"材质编辑器里选中了哪些材质"。
→ 插件自己维护候选列表 + 勾选状态（`NprPickerItem`）。

## 四、数据存储

| 数据 | 存在哪里 | 随 `.blend` 走？ |
|---|---|---|
| 材质组（参数 + 材质列表） | `Scene.npr_settings.groups` | ✅ |
| 候选材质列表 | `Scene.npr_settings.picker_items` | ✅ |
| 操作日志（最近 200 条） | `Scene.npr_settings.log_entries` | ✅ |
| 材质归属元数据 | 材质的自定义属性 `npr_group` / `npr_part` | ✅ |
| 描边外壳归属 | 对象的自定义属性 `npr_outline_of` | ✅ |
| 节点组 | `bpy.data.node_groups`（`NPR_*`） | ✅（带版本标记，可重建） |
| 插件启用状态 | Blender 用户偏好 | ❌（跟机器） |

节点组带版本标记 `npr_ng_version`。插件升级后版本号变化，`ensure_all()` 会
**原地重建**（清空节点重填接口），因此不会丢材质里的引用。

## 五、验证与自检

「高级 / 工具」面板提供：

- **自检**（`npr.validate`）：检查 18 个节点组是否齐全、连线是否有效、
  参数名能否绑定到主组接口、View Transform 是否合适
- **重建节点组**（`npr.rebuild_node_groups`）：强制按当前版本重建
- **日志**：最近 200 条，分 INFO / WARN / ERROR

命令行验证脚本（在插件目录的 `tools/` 下）：

| 脚本 | 作用 | 期望结果 |
|---|---|---|
| `tools_dev_check.py` | 节点组结构 + 接口与参考文件一致性 + 参数绑定 | `failures=0` |
| `tools_func_check.py` | 12 步功能测试（含 EEVEE 渲染断言） | `fails=0` |
| `tools_verify_direct.py` | 颜色端到端（蓝色应为精确 `(0.1,0.2,1.0)`） | `✓ 正确` |
| `tools_iso_branches.py` | 分支隔离（先渲染纯红对照，再逐个关分支） | `01_all_on` 即精确蓝色 |
| `tools_ascii_view.py` | PNG 转终端字符缩略图 | — |
